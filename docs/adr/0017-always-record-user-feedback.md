# ADR 0017: ユーザーの指摘を必ず記録し毎セッション引き継ぐ

- 状態: 採用
- 日付: 2026-10-23
- 決定者: ユーザー

## 背景

ユーザーから「指摘はADRに残してくださいね」「指摘は絶対に残すということをメモして毎セッション必ず読まれるようにしてください」と指定された。ADR 0002は決定事項の記録を定めているが、修正指摘を必ず記録する義務と、セッション開始時に過去の指摘を読み直す手順を明確にする必要がある。

直前の「お辞儀をしない」「手で直す動きで顔を隠す」「背景もキャラクターと同じ作画にする」という指摘は、ADR 0016に原文・対応・暫定解釈を記録済みである。

## 決定内容

- ユーザーの指摘・修正要求・禁止事項・好みは、大小を問わず必ず `docs/adr/` に記録する。修正の実施だけでは完了にしない。会話、一時的な作業メモ、自動メモリだけに残すことは禁止する。
- 指摘を受けた同じ作業内で、指摘の原文または意味を変えない要約、対象・適用範囲、対応内容、対応状況、未解決点を記録する。曖昧な表現は原文とエージェントの解釈を分ける。
- 新しい判断や既存方針の変更は連番の新規ADRにする。同じ指摘への対応状況や説明の補足は既存ADRへ追記してよい。変更する場合は後継・置換の参照を残す。
- ADR一覧に「ユーザー指摘の引き継ぎ」を設け、有効な指摘を含むADRを列挙する。新しい指摘の記録時にこの一覧も更新する。後継ADRができた場合は最新の参照と適用範囲を明記する。
- 毎セッション開始時・再開時・引き継ぎ後、作業前に `AGENTS.md`、ADR一覧、本ADR、「ユーザー指摘の引き継ぎ」に載せた有効なADRの本文を必ず読む。続けて作業に関連するADRも読む。前の会話を覚えていることを省略理由にしない。
- この義務をルートの `AGENTS.md` に明記し、`AGENT.md`、`CLAUDE.md`、`.claude/rules/adr.md` にも同じ開始手順と記録義務を置く。
- 記録するためだけに追加の承認を求めない。ユーザーが指示した内容と、実装上の仮定・未決事項を区別する。

## 理由

会話が変わっても指摘を失わず、同じ誤りを繰り返さないため。起動時に参照するプロジェクトの指示ファイルと永続的なADRを結び付け、記録と読み直しの両方を作業手順として必須にする。

## 影響

- ADR 0002の記録対象と作業開始手順を本ADRで補強する。既存の提案・採用・置換の区別と履歴保存ルールは継続する。
- 以後の完了判断には、指摘のADR記録と引き継ぎ一覧の更新を含める。
- プロジェクトの指示ファイルを読むエージェントに対する必須手順として永続化する。指示ファイルを読み込まない外部ツールまで、技術的に自動実行を保証するものではない。
- 人物設定・台本・動画素材・出力動画は本ADRでは変更しない。
