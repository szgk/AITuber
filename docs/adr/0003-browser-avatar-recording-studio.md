# ADR 0003: デザインver1のブラウザアバターと動画収録

- 状態: 一部置換（事前制作動画の主収録経路は[ADR 0015](0015-full-body-short-production.md)へ移行。配信用収録室は継続）
- 日付: 2026-10-23

## 背景

デザインver1をVTuberのように動かし、ショート動画・ロング動画をHTML、CSS、JavaScriptで収録したい。現在の素材は1枚のデザインシートであり、Live2D用のパーツ分けPSDやCubismモデルはない。

## 決定内容

`frontend/studio/` にローカル収録アプリを追加する。Canvas 2Dで原画の全身部分を切り出し、外周の白背景を除去して、揺れ・呼吸・瞬き・口の合成を行う。表情は通常・微笑み・びっくりを用意する。表情の合成は実装用の表現であり、新しいキャラクター設定の確定ではない。

描画と録画はブラウザ標準のCanvas 2D、Web Audio API、MediaRecorderを使用し、外部の描画ライブラリは導入しない。現時点ではメッシュ変形やCubismモデルを必要とせず、追加依存を導入する利点が小さいためである。Web Audioでマイク・音声ファイルを解析し、同じ音声を録画へ混合する。

ユーザーの追加指示により、音声ファイルによる収録を基本とし、マイクは初期状態では接続せず折りたたみの補助設定とする。

縦1080×1920と横1920×1080、30fpsの映像出力、手動字幕送り、背景・画角・倍率変更、録画の停止・一時停止・再開を実装する。利用可能なコーデックを検出しWebMを優先し、対応する環境ではMP4へフォールバックする。拡張子の変更だけでMP4に変換しない。

長時間収録ではFile System Access APIがある環境で保存先を指定して1秒単位でディスクへ書き込む。その他の環境ではメモリ上に保持して停止時にダウンロードするため、長時間収録にはディスク保存またはOBSを案内する。OBS用出力画面は同一オリジン・同一ブラウザのBroadcastChannelで同期し、OBSのウィンドウキャプチャで使用する。

## 理由

パーツ分けやモデル制作を待たずにver1の原画を使用できる。ブラウザ標準APIでオフライン動作でき、ランタイムの外部CDN・クラウド・APIキーは不要。Node.js標準モジュールのみのローカルHTTPサーバーを起動入口とする。

## 影響と制約

- パーツごとの髪の物理演算・顔の立体変形・カメラによる顔追跡は含まない。Live2D Cubismモデル互換ではない。本格的なLive2D化は別途パーツ素材とモデル制作を要する。
- 1枚絵からの背景除去と顔への合成のため、輪郭の白フチや表情のなじみには制約がある。
- 収録は実時間。ブラウザを非表示にすると描画が制限される。長時間の耐久性は利用端末ごとに確認する。
- ブラウザの対応状況によりコーデックと保存方式が異なる。マイクにはブラウザの許可が必要。
- AI台本生成・音声合成・自動投稿・自動配信は本実装に含めない。既存のPython推論経路とは独立する。
- ADR 0001の将来構想のうちアバターとローカル収録部分を追加する。既存推論設計の置換ではない。
