# ADR 0002 設定と決定事項をADRで管理する

- 状態: 採用
- 日付: 2026-10-23
- 決定者: ユーザー

補足・後継: [ADR 0017](0017-always-record-user-feedback.md)で、ユーザーの指摘を必ず記録する義務と毎セッション開始時の読み直し手順を追加した。本ADRの記録形式・状態区分・履歴保存方針は継続する。

## 背景

望月京子のショート動画とロング動画の制作に向けて、日常設定と企画を継続的に増やしていく。ユーザーから「設定や決定事項はADRとして残していく」「CLAUDE.md, AGENT.md, .claudeなどに残す」と指示があった。

## 決定

キャラクター設定、世界観、動画制作方針、技術設計、運用の決定事項を `docs/adr/` に記録する。共通作業ルールはルートの `AGENTS.md` に置き、`AGENT.md`、`CLAUDE.md`、`.claude/rules/adr.md` から参照できるようにする。

ADRは4桁の連番と内容を表すファイル名で作成し、`docs/adr/README.md` に追加する。状態、日付、背景、決定内容、理由、影響、関連資料を記載する。未決事項があれば明記する。

状態は「提案」「採用」「置換」「却下」を基本とする。既存実装の遡及記録には、ADR 0001のように「現行実装の記録」と明記する。記録指示だけで、過去の企画案が採用されたとは扱わない。

決定を変える場合は後継ADRを作成し、変更理由と元のADRへのリンクを記す。元のADRには後継へのリンクと置換状態を追記し、当時の決定と理由を保存する。誤字や意味を変えない補足は同じADRで修正してよい。

台本、企画一覧、詳細な設定資料は別ファイルに保持してよい。決定事項はADRに記載し、詳細資料と相互参照する。実行用プロフィールや学習データへの反映は、ADRへの記録とは別に扱い、反映範囲を記録する。

## 理由

決定の内容だけでなく、理由と変更の経緯を追跡できるようにする。複数のエージェントが異なる入口から作業しても、同じ設定と決定を参照できるようにする。

## 影響

- 作業開始時に関連ADRを確認し、新たな決定を行った作業ではADRと一覧も更新する。
- 設定案の作成と採用を区別し、提案を勝手に確定しない。記録するためだけに追加の承認手順は設けない。
- 既存の京子の日常設定と動画企画は初期案のままとし、個別の採用判断を今後のADRで記録する。
